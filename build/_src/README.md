# 빌드 알림 아이콘 — 원본과 재생성

`build/*.png` 는 **여기서 생성된 산출물이다. 직접 편집하지 않는다.**
모양이나 색을 바꾸려면 `icons.js` 를 고치고 다시 뽑는다.

Adaptive Card 의 헤더 아이콘 자리에 쓰는 512x512 투명 PNG다.

## 구성

| 경로 | 역할 |
|---|---|
| `icons.js` | 유일한 원본. 글리프 path, 색, 배지 조립 규칙 |
| `Build-Icons.ps1` | SVG 생성 → Chrome 헤드리스로 PNG 래스터라이즈 → 투명도 검증 |
| `svg/*.svg` | 생성된 벡터 원본. 다른 도구에 넘길 때 쓴다 |
| `../*.png` | 실제로 참조되는 512x512 투명 PNG |

## 재생성

```powershell
pwsh ./Build-Icons.ps1              # 전부
pwsh ./Build-Icons.ps1 -Only ci     # 하나만
```

Node.js 와 Chrome(없으면 Edge)이 필요하다. 별도 이미지 도구는 필요 없다.
재생성은 결정적이다 — 정의가 그대로면 같은 바이트가 다시 나온다.

## 스타일: 색 판 + 흰 글리프

색으로 채운 둥근 사각 배지 위에 **흰색** 글리프를 얹는다.

글리프를 흰색으로 고정하는 것이 핵심이다. PNG 는 뷰어의 테마에 반응하지 못하는데,
흰 글리프는 어떤 색 판 위에서도 대비가 확보되므로 라이트/다크 양쪽에서 똑같이 읽힌다.

### 폐기한 안 — 배경판 없이 컬러 글리프만

판 없이 글리프만 색으로 칠하는 안을 함께 만들어 실측했다. 카드가 훨씬 조용하고
깔끔했지만 **채널을 훑을 때 종류가 눈에 덜 들어와** 배지 쪽을 택했다.

부수적으로 확인한 것: 판이 없으면 글리프 자체가 색이라 **어두운 색이 다크 테마에서
묻힌다.** 회색(`#6B7280`)을 `#8C97A8` 로 올려야 겨우 보였다. 배지 방식은 색을 판에
칠하고 글리프가 흰색이라 이 문제가 아예 없다.

## 아이콘 목록

**종류** (시작 카드) — `ci` `cd` `client` `server` `lod` `data` `script` `navmesh`
`localize` `test` `merge` `ddc` `perforce` `serverExec` `default`

**상태** (종료 댓글) — `success` `unstable` `warning` `failed` `aborted`

`default` 는 종류를 특정하지 못했을 때 떨어지는 자리다. 새 종류를 넣기 전까지
그 자리를 메운다.

색은 두 번째 단서다. 종류를 가르는 것은 모양이고, 색은 채널을 훑을 때 덩어리로
먼저 눈에 들어오게 하는 역할이다. 그래서 색상환에서 되도록 벌려 잡되 완전한 중복
회피에 매달리지 않는다.

## 사용 크기

Adaptive Card `Image` 의 `width` 로 지정한다. 데스크탑·모바일 모두에서
20/24/28/32/40px 를 실측했고 전부 정상 렌더된다.

| 자리 | 폭 |
|---|---|
| 시작 카드 헤더 | `32px` |
| 종료 댓글 헤더 | `24px` |

## 지켜야 할 것

- **512x512 투명 PNG.** 흰 배경이 구워지면 다크 테마에서 흰 상자로 보인다.
  `Build-Icons.ps1` 이 모서리 알파를 검사해 이 실수를 막는다.
- **글리프는 48x48 viewBox, 중심 (24,24).** 새 아이콘도 같은 좌표계를 쓴다.
- **색은 `currentColor` 로 둔다.** 그래야 배지가 글리프를 흰색으로 덮어쓸 수 있다.
- 화살촉이 있는 글리프는 **선 두께의 3배 이상 폭**으로 잡고 선을 밑동보다 조금
  일찍 끊는다. 그러지 않으면 둥근 선끝이 삼각형 밖으로 삐져나와 홈처럼 보인다.
